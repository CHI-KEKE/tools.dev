Request / Response 通用處理流程

從外部呼叫進入 IIS，到 Controller → Service → Repository → DB，再包裝回統一格式 JSON 回應的完整管線。本頁根據實際程式碼盤點整理，標註各環節對應的檔案位置。

ASP.NET Web API 2 · .NET Framework 4.6.2 Autofac 依賴注入 EF 5.0 + Dapper FluentValidation ELMAH + App Insights 121 Controllers · 258 Services
01

整體管線總覽

由左至右依序執行 · 例外會在任一環節被攔截
Client

外部呼叫

WebSite/Controllers/Apis/*.cs

DataAccess/Repositories/*.cs

SQL Server

Response

統一輸出

回應再經 UnifiedResultHandler 包裝成固定格式 ApiResultEntity 回給呼叫端。

例外分支： 任一環節拋出例外，都會被 GlobalExceptionHandler 攔截，依例外類型轉成統一格式錯誤 JSON，並同步寫入 ELMAH（含 ErrorId）與 Application Insights。
02

Request 進入細節

信封格式解包

呼叫端送出的 Body 並非直接是業務 JSON，而是包一層 Data 欄位的字串。
// ApiRequestEntity.cs
public class ApiRequestEntity {
  public string Data { get; set; }
}
BusinessLogic/BE/Apis/ApiRequestEntity.cs

Token 簽章驗證

部分 API 使用自家 Token + Timestamp + Signature 機制，非標準 IIS Auth。
// ValidateTokenAttribute.cs
var token = Request.Params["t"];
var ts    = Request.Params["ts"];
var sig   = Request.Params["s"];
// SHA512(ts + data + saltKey) == sig ?
Extensions/ActionFilters/ValidateTokenAttribute.cs

JWT 驗證（另一種方式）

部分 API 改用 JWT AccessToken，並比對 Body 內 ShopId 與 Payload 是否一致。
// ValidateJWTAttribute.cs
var payload = JwtBuilder.Create()
  .WithAlgorithm(new HMACSHA256Algorithm())
  .MustVerifySignature()
  .WithSecret(secret)
  .Decode<IDictionary<string,object>>(accessToken);
Extensions/ActionFilters/ValidateJWTAttribute.cs

Request Log 記錄

記錄 IP / Method / URL / 參數，並讀取 Gateway 帶入的 N1-TRACE-ID 做跨服務追蹤。
// LogRequestAttribute.cs
Logger.Trace($"{ip} | {method} | {url} | {parameters}");
if (headers.TryGetValues("N1-TRACE-ID", out v))
  Logger.Trace($"N1-TRACE-ID : {traceId}");
Extensions/ActionFilters/LogRequestAttribute.cs
03

Response 統一格式

Controller 回傳的原始資料，會再經一層包裝

成功回應

Controller 呼叫 this.Ok(result) 後的最終輸出。
{
  "ErrorId": "",
  "Status": "Success",
  "Data": { ...業務資料... },
  "ErrorMessage": "",
  "TimeStamp": "2026-07-27T15:00:00"
}

錯誤回應

由 GlobalExceptionHandler 依例外類型組出的統一格式。
{
  "ErrorId": "a1b2c3d4",
  "Status": "Failure",
  "Data": null,
  "ErrorMessage": "Signature not valid",
  "TimeStamp": "2026-07-27T15:00:00"
}
例外情況： 有一份路徑白名單（如 virtualpayment、realtimeshippingorder、PDF 下載、ops/healthcheck 等）會跳過 UnifiedResultHandler 包裝，直接回傳原始 Response——代表「統一格式」並非 100% 統一，屬於已知的不一致設計。

GlobalExceptionHandler.cs

05

已知設計問題

供架構搬遷 / 重構時參考
問題說明影響
驗證機制不統一 同時存在 Token 簽章（t/ts/s）與 JWT 兩套驗證方式，依 Controller 各自掛 Attribute，沒有集中管理。 中
統一輸出有白名單例外 UnifiedResultHandler 對特定路徑（PDF、金流 callback 等）直接略過包裝，格式不一致。 中
全同步（無 async/await） Controller → Service → Repository 全鏈路同步呼叫，DB 逾時會直接卡住 ThreadPool 執行緒。 高
單一 Repository 專案耦合 12 個資料庫 DA.Repositories 直接引用 WebStore/ERP/CRM/NineYiDW 等 12 個資料庫專案，違反單一服務單一資料庫原則。 高
