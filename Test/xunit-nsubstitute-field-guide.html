A Field Guide to .NET Testing Companions

xUnit 與 NSubstitute

兩個角色、一套分工——測試框架與替身框架的完整解剖

PLATE No. 07 · MemberCollectionAuditServiceTests 標本採集紀錄

在 .NET 的單元測試世界裡，常有人把「測試框架」和「Mock 框架」混為一談，以為裝一個套件就能解決所有問題。實際上這是兩種完全不同職責的工具：一個負責「定義測試、執行測試、判斷成敗」；另一個負責「假扮外部依賴、觀察互動行為」。

這份筆記以我們在 MemberCollectionAuditServiceTests 中實際使用的程式碼為標本，逐一拆解 xUnit 與 NSubstitute 的角色定位、核心能力，以及兩者如何協作，讓一段沒有回傳值的稽核流程也能被完整驗證。

分工總覽
STANDARD No. 01

xUnit

genus: Testing Framework
角色：測試執行者 / 裁判

負責回答「這是不是一個測試？」「要不要執行？」「跑完之後算過還是不過？」xUnit 是測試的骨架與裁判，本身完全不知道 IPromotionHttpClient 或 MemberCollectionAuditService 是什麼，它只認得屬性標記與斷言結果。

識別特徵
[Fact]／[Theory]／Assert.*
生命週期
每個測試方法執行前都會 new 一份全新的測試類別實例，建構子等同每個測試獨立的 Arrange 起點，測試之間互不干擾狀態
判斷依據
方法內是否拋出未被捕捉的例外／Assert 是否失敗
STANDARD No. 02

NSubstitute

genus: Mocking / Test-Double Framework
角色：依賴的替身 / 臥底

負責回答「當這個介面被呼叫時，要回傳什麼？」「它到底有沒有被呼叫、呼叫了幾次、帶了什麼參數？」NSubstitute 是假扮外部世界的工具，讓受測物件以為自己在跟真正的 Repository、HttpClient 對話，實際上全部被攔截記錄。

識別特徵
Substitute.For<T>()／.Returns(...)／.Received()
運作原理
在執行期用 Castle DynamicProxy 動態產生一個實作該介面的代理類別，攔截每一次方法呼叫並記錄下來
判斷依據
呼叫次數、傳入參數是否符合預期條件（Arg.Is／Arg.Any）
SPECIMEN BEHAVIOR — xUnit

本次程式碼中最基本的用法：一個 [Fact] 對應一段固定情境，配合 [Trait] 標記所屬方法分類，方便未來依類別篩選執行。

MemberCollectionAuditServiceTests.csxUnit 特徵標記
[Fact]
[Trait("Category", nameof(MemberCollectionAuditService.AuditByRedisDataAsync))]
public async Task AuditByRedisDataAsync_全部MemberCollection皆為FIRST_PURCHASE_過濾後應提早結束不呼叫Match()
{
    // Arrange — 準備情境
    // Act    — 執行受測方法
    // Assert — xUnit 判斷：方法內若無 Assert 失敗、無未捕捉例外 → 綠燈
}
xUnit 在這裡做了什麼辨識這是一個測試方法、非同步執行它、蒐集執行結果（成功／失敗／例外訊息），彙整成報表輸出 Passed: 6, Failed: 0。
xUnit 沒有做的事它完全不知道 MemberCollectionAuditService 內部邏輯，也不負責準備假資料——那是 NSubstitute 的工作。
SPECIMEN BEHAVIOR — NSubstitute

真正的主角戲份。以下完整重現 Case 03（下游查詢失敗仍需保留 Id）如何用 NSubstitute 建構、操控、驗證：

MemberCollectionAuditServiceTests.csNSubstitute 三段式：建立 → 設定 → 驗證
// ① 建立替身：讓 Castle DynamicProxy 動態產生一個假的 IPromotionHttpClient
private readonly IPromotionHttpClient _promotionHttpClient = Substitute.For<IPromotionHttpClient>();

// ② 設定行為：指定「特定參數」呼叫時要回傳什麼、或要拋出什麼
_promotionHttpClient.GetMemberCollectionDataAsync(normalId, Arg.Any<IDictionary<string,string>>())
    .Returns(new GetMemberCollectionsResponseEntity { CollectionId = normalId, CollectionTags = new() });

_promotionHttpClient.GetMemberCollectionDataAsync(failedId, Arg.Any<...>())
    .Throws(new HttpRequestException("下游服務逾時"));

// ③ 驗證互動：呼叫結束後，確認「該用什麼參數呼叫了誰、呼叫了幾次」
await _promotionHttpClient.Received(1).MemberMatch(
    Arg.Is<MemberMatchRequestEntity>(x =>
        x.MemberCollectionIdList.Contains(normalId) &&
        x.MemberCollectionIdList.Contains(failedId)),
    Arg.Any<...>());
Returns — 操控回傳值讓假物件「配合演出」，回傳我們想測試的資料形狀，而不需要真的連上 webapi 或資料庫。
Throws — 模擬失敗不需要真的讓網路斷線，一行程式碼就能重現「下游逾時」這種平常很難重現的情境。
Arg.Is / Arg.Any — 精準比對Arg.Any 代表「不管傳什麼都符合」；Arg.Is(x => ...) 則是自訂 lambda 條件，讓兩筆不同 Id 各自觸發不同回應。
Received(1) — 行為驗證因為受測方法沒有回傳值，這是唯一能斷言「邏輯真的照我們預期跑」的方式：確認 MemberMatch 被呼叫恰好一次，且參數內容正確。

Capability Matrix

能力比對表

同一個問題，兩個框架給出完全不同層次的答案。

問題xUnit 的答案NSubstitute 的答案
「這段程式碼算不算一個測試？」 [Fact] / [Theory] 標記即為一個可執行單位 不關心，NSubstitute 只在測試「內部」運作
「外部服務要回傳什麼？」 不知道，也不負責 .Returns(...) 指定假資料
「怎麼模擬下游逾時？」 不負責 .Throws(new HttpRequestException(...))
「這個方法真的被呼叫了嗎？」 不負責 Received(1) / DidNotReceive()
「同一批資料要跑很多組參數？」 [Theory] + [InlineData] 不負責（資料驅動是 xUnit 的職責）
「最終算 Passed 還是 Failed？」 方法執行完是否有未捕捉例外 / Assert 失敗 不負責判決，只提供驗證依據
Why This Pair

為什麼是這一組，而不是其他組合

.NET 生態圈常見替代方案：NUnit / MSTest（測試框架）、Moq / FakeItEasy（Mock 框架）。以下是選擇 xUnit + NSubstitute 的實際考量。

01 / 延續性

repo 既有慣例

這兩個 repo（webapi / worker）的既有測試（如 PromotionEngineServiceTest）本來就是 xUnit + NSubstitute 組合，延續一致性比引入新工具更重要。

02 / 語法簡潔

NSubstitute 幾乎零樣板

相較 Moq 需要 new Mock<T>() 再取 .Object，NSubstitute 的 Substitute.For<T>() 直接就是可注入的實例，語法更貼近自然語言。

03 / 生態成熟

xUnit 是 .NET 社群主流

比 MSTest 更輕量、不需要 [TestClass] 樣板；比 NUnit 更貼近「每測試獨立實例」的隔離哲學，天生適合搭配 Mock 框架使用。

Glossary

關鍵詞速查

[Fact]
xUnit：標記一個「固定情境、不需參數」的測試方法。
[Theory]
xUnit：標記一個「需要外部資料驅動、可重複執行多組參數」的測試方法，通常配合 [InlineData]。
[Trait]
xUnit：為測試加上分類標籤，方便依 --filter 篩選執行，不影響測試邏輯本身。
Substitute.For<T>()
NSubstitute：為介面 T 動態產生一個假物件（替身），預設所有方法回傳型別預設值（null / 0 / false）。
.Returns(...)
NSubstitute：設定替身在被呼叫時要回傳的固定值，也支援用 callInfo => ... 依傳入參數動態計算回傳值。
.Throws(...)
NSubstitute：設定替身在被呼叫時直接拋出指定例外，需另外 using NSubstitute.ExceptionExtensions;。
Arg.Any<T>()
NSubstitute：萬用比對子，代表「不論傳入什麼值都符合」這個設定。
Arg.Is<T>(x => ...)
NSubstitute：條件比對子，只有滿足 lambda 條件的呼叫才會套用這個 .Returns / 被這個 Received 認列。
Received(n)
NSubstitute：斷言某方法「確實被呼叫了 n 次」，是驗證無回傳值方法行為的核心手法。
DidNotReceive()
NSubstitute：斷言某方法「完全沒有被呼叫過」，常用於驗證提早 return 的分支。
