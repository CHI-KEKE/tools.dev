只取「區間內最後一筆」應觸發時間的問題

情境：某任務一天觸發 3 次（08:00 / 12:00 / 15:00），目前程式只會檢查其中 1 次，其餘 2 次完全沒被驗證。

1現狀：目前程式碼在做什麼

GetExpectedLastRunTime 只回傳「最後一筆」

var runTimes = task.GetRunTimes(windowStart, windowEnd, 1000);
return runTimes.Length > 0 ? runTimes[^1] : null;   // 只取陣列最後一個元素！

task.GetRunTimes() 其實會老實地回傳區間內「所有」應觸發時間點的完整清單， 但程式碼用 [^1] 只挑出陣列最後一筆，其餘全部被捨棄。

2時間軸圖解：早上 8:00 巡檢時實際發生什麼事

假設每天巡檢一次，時間點設在早上 08:00；任務前一天有 3 個排定時間點

結論：目前巡檢只會驗證「昨天 15:00」這一筆。如果「昨天 08:00」或「昨天 12:00」那次因為機器問題沒有執行， 系統完全不會發現、也不會告警，因為程式根本沒去看這兩筆。

3對照：修正後應該長什麼樣子

改成檢查「區間內所有」應觸發時間點，而不是只取最後一筆

// 修正方向：回傳全部時間點，而非只取最後一筆
public IEnumerable<DateTime> GetExpectedRunTimes(string taskPath, DateTime windowStart, DateTime windowEnd)
{
    using var ts = new TaskService();
    var task = ts.GetTask(taskPath);
    if (task == null) return Enumerable.Empty<DateTime>();
    return task.GetRunTimes(windowStart, windowEnd, 1000);  // 全部回傳
}

// CheckTask 改成對每一筆各自判斷
foreach (var expectedRunTime in expectedRunTimes)
{
    // 對這一筆各自找對應的執行紀錄，各自判斷漏排 / 失敗
}
