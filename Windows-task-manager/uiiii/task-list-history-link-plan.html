問題與需求

⚠️ 現況缺口
缺口影響
任務清單與執行歷史頁面 沒有連結 使用者搜尋到目標排程後，還要跳頁、手動在下拉選單重新找一次同一個任務，多花 2～3 個步驟
執行歷史頁面 需要手動判斷 Tab 是「一般 Task」還是「ETL Flow」 使用者要自己記得該任務屬於哪個分類才能選對 Tab，容易選錯或找不到
無法快速定位失敗紀錄 執行歷史清單預設顯示全部（含成功），若只想看失敗需要人工往下捲動尋找紅色徽章
🎯
你的需求：在「Windows 排程任務管理」頁面，針對搜尋到 / 顯示出來的每一筆排程， 可以直接點擊就前往該任務的執行歷史與失敗 Log，不需要再跳轉頁面手動選取。

建議做法

✅ 規劃方案

3.1　在每張任務卡片 / 每一列新增「執行歷史」按鈕

在既有的 編輯／啟用/停用 按鈕群組旁，新增一顆按鈕， 直接帶入該任務的路徑與分類，跳轉到 /Tasks/History 並自動代入篩選：

// 產生連結時自動判斷任務類型（複用既有的 IsEtlTask 邏輯）
var taskType = _taskSchedulerService.IsEtlTask(task) ? "etl" : "general";
var historyUrl = $"/Tasks/History?taskName={Uri.EscapeDataString(task.Path)}&taskType={taskType}";

3.2　History 頁面依網址參數自動定位

HistoryModel.OnGet 已經支援 taskName + taskType 參數， 這部分不需改邏輯，只要確保連結帶對值，頁面開啟後就會自動：

  • 切到正確 Tab（一般 Task／ETL Flow）
  • 下拉選單自動選取該任務
  • 直接顯示該任務的完整執行歷史清單

3.3　新增「只看失敗」快速篩選（可選加強）

在 History 頁面篩選區塊加一個 只看失敗 切換開關（沿用現有 Result 欄位過濾）， 並讓「任務清單」按鈕可以直接帶 onlyFailed=true 參數跳轉，方便使用者一鍵定位失敗紀錄：

// History.cshtml.cs 新增查詢參數
public void OnGet(string? taskName, string taskType = "general", bool onlyFailed = false)
{
    ...
    History = onlyFailed
        ? History.Where(h => h.Result == "Failed")
        : History;
}
