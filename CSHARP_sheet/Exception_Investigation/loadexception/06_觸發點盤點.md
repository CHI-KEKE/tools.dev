# ERPDBEntitiesV2 觸發點完整盤點

## 觸發根本條件

不是「cfn」本身造成問題，而是底層呼叫了 `ObjectContext.CreateQuery<T>`：

```
任何觸發 ObjectContext.CreateQuery<T> 的呼叫
  → ImplicitLoadAssemblyForType
  → AssemblyCache.LoadAssembly
  → Assembly.GetTypes()
  → ReflectionTypeLoadException（若有版本衝突）
```

## 為什麼一般 LINQ 沒有爆

```
一般 LINQ 路徑：
  DbContext.Set<T>().Where(...)
  → EF 在這個路徑「跳過載入失敗的 Assembly」
  → 只要 Entity 型別本身能載入，就繼續跑

ObjectContext.CreateQuery<T> 路徑：
  → 嚴格掃描所有 Assembly
  → 任何 type 載入失敗直接拋出，不跳過
```

**LINQ 的掃描寬容，CreateQuery 嚴格。**

## 最危險的觸發點

`TaskHelperRepository.csp_CreateNmqV2Task`：

```csharp
// ERPDB.Context.cs
return ((IObjectContextAdapter)this).ObjectContext
    .ExecuteFunction("csp_CreateNmqV2Task", ...);
```

NMQ 每建立一個 Task 就呼叫，理論上每個 job 都在踩這顆雷。  
生產環境沒事是因為 GAC 有保護，CI/本機沒有 GAC 才爆。
