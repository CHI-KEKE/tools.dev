Chapter 01

🔍 案發現場

一份定期購系統架構文件，有個精心設計的 tab 切換功能，可以在 C4 Context、C4 Container、Sequence Diagram 之間切換。 圖表渲染正常，按鈕樣式正確，視覺上一切看起來都很好。

但是——點下去，什麼反應都沒有。

🚨 症狀 按鈕有 cursor: pointer，有 onclick="showDiag(...)"，卻完全無法切換 tab。 情境時間軸的另一組 tab 也同樣失效。

第一反應：是 Mermaid.js 的問題嗎？是 display:none 的元素沒有渲染嗎？

加了 mermaid.run()，還是沒用。加了 setTimeout，還是沒用。懷疑過 CDN 載入時序，懷疑過 CSS 層疊，就是沒想到最單純的那個可能。

Chapter 02

🪄 第一個線索：殭屍程式碼

仔細翻 script block，在 showScenario() 函式結尾的 } 之後， 赫然出現了 32 行孤立的物件資料——這是幾個版本前被刪除的舊架構殘留， 沒有變數宣告，直接暴露在頂層：

script block（有問題的版本） 
function showScenario(key) {
  // ... 正常的函式內容 ...
}   // ← 函式結束

// ⚠️ 這些是殘留資料，沒有任何變數宣告，直接暴露在頂層！
  success: [
    { day:0, label:'消費者首購', emoji:'🛒', ... },
    { day:0, label:'RegularOrderInitJob', ... },
    // ... 30 行 ...
  ],
  fail: [ ... ],
  pending: [ ... ],
};

這在 JavaScript 裡是語法錯誤。刪掉之後……還是沒有用。

所以有第二個 bug，而且更隱蔽。

Chapter 03

💀 真正的兇手：消失的 </script>

檢查 script block 的結尾，發現了讓人目瞪口呆的事：

index.html（問題版本）— script 尾端 
  function showDiag(key) {
    // ...
  }
  showDiag('c4ctx');

<!-- ❌ 這裡應該有 </script>，但它不見了 -->

</body>
</html>
🔴 問題核心 </script> 標籤遺失。HTML parser 看不到它，就永遠不知道 script 在哪裡結束。
Chapter 04

🧠 瀏覽器 Parser 的視角

要理解為什麼這麼嚴重，需要了解瀏覽器解析 HTML 的規則。 HTML parser 在遇到 <script> 時，會進入特殊模式：

📖 HTML Parser 行為模擬

<script> → 🔀 進入 Script 模式，停止解析 HTML
function showDiag() {...} → ✅ 解析為 JavaScript 程式碼
</body> → ⚠️ 仍在 Script 模式！當成 JS 文字，不是 HTML tag
</html> → ❌ 仍在 Script 模式！整份文件已結束，script 從未執行
⚖️

HTML Parser 的鐵律

<script> 開始的區塊，只有 </script> 才能結束它。
</body>、</html>、檔案結尾——全部無效。
沒有 </script>，整個 script block 靜默地從未被執行。

這就是為什麼所有函式都定義了，onclick 也寫了，但點按鈕完全沒反應—— showDiag 和 showScenario 根本不存在於全域。

Chapter 05

✅ 修復與還原

1

刪除殭屍程式碼

移除 showScenario() 結尾後的 32 行孤立 SCENARIOS 物件資料。這消除了語法錯誤，但 tab 仍然無法切換。

2

找到真正的根本原因

仔細確認 script block 結尾，發現 </script> 完全缺失。

3

補上一行，全部修復

在 showDiag('c4ctx'); 後加上 </script>，兩組 tab（情境時間軸 + 架構圖）立即全部正常。

修復後的正確寫法 
  showDiag('c4ctx');

</script>  ← 就是這一行，缺一不可
</body>
</html>
Chapter 06

📌 帶走的教訓

🔒

Script 有且只有一種結束方式

</script> 是唯一能結束 script block 的 token。任何其他 HTML tag 在 script mode 下都是透明的。

🔇

這個錯誤不會有警告

瀏覽器不會報錯，頁面也可以正常渲染。只有 JS 函式靜默地從未存在，onclick 呼叫靜默地失敗。

🧹

清理殘留程式碼

舊版本的殘留資料若沒有對應的變數宣告，直接暴露在頂層會造成語法錯誤。刪除時要確保完整。

🐛

Debug 要從最基礎的開始

onclick 完全沒反應時，第一步應該是確認函式是否真的被定義，而不是假設函式存在去追更複雜的邏輯。

✅ 快速排查 checklist onclick 無反應時：① 打開 DevTools Console 確認有無 JS 錯誤 → ② 直接在 Console 呼叫函式名稱確認是否存在 → ③ 確認 <script> 是否有對應的 </script>
