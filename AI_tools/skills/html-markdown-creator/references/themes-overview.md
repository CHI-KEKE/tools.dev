# 視覺主題總覽

6 種可選視覺主題，完整 CSS/HTML 都放在 `assets/themes/*.html`，每個檔案開頭都有註解說明適用情境、不適合情境，以及對應到 `assets/sidebar-layout-template.html` 的 `--doc-*` CSS 變數映射值。動筆前把對應主題檔整份讀進來當作元件抄寫來源，不要憑印象重寫 CSS。

| 主題檔 | 名稱 | 語意基調 | 適合情境 |
|---|---|---|---|
| `warm-paper-style.html` | 暖紙白皮書風 | 中性、專業、知識型 | 技術分析、架構說明、機制拆解，沒有明顯危險/分類語意時的預設選擇 |
| `mysql-dolphin-style.html` | MySQL 海豚藍橘風 | 資料庫/後端調性 | 資料庫設計、SQL 相關、後端服務分析 |
| `organic-glass-style.html` | 有機玻璃綠風 | 分類裝飾語意（非風險分級） | 自然/生活/品牌調性主題，多分類並列說明 |
| `cozy-meadow-style.html` | 舒心草原暖棕風 | 分類裝飾語意（非風險分級） | 溫馨、生活化、教學導向的內容 |
| `case-file-style.html` | 復古病歷表／案卷風 | 紅=危險、琥珀=待觀察、綠=已解決 | 事件回顧、故障排查、異常紀錄、多案例對照，需要風險分級語意 |
| `blue-ghost-style.html` | 斑馬線幽靈藍風 | 分類裝飾語意（非風險分級），可愛詼諧調性 | 輕鬆詼諧的技術小品、生活隨筆、新手導覽/入門說明，想要可愛放鬆而非嚴肅專業觀感的內容 |
| `mint-tokens-style.html` | 薄荷設計令牌風 | 分類裝飾語意（非風險分級），乾淨柔和調性 | 設計系統/UI 規範說明、產品功能介紹、輕量級技術規劃文件，想要「圓潤、柔和、乾淨」而非企業感的內容 |
| `harbor-ledger-style.html` | 港灣日誌風 | 分類裝飾語意（非風險分級），沉穩高對比調性 | 治理型文件、規範文件、稽核報告、決策紀錄，想要「深海軍藍＋米杏紙感＋磚紅重點」高對比、有份量感而非糖果色系的內容 |
| `system-architecture-style.html` | 系統架構圖風 | 架構導向、服務依賴、流程導向，薄灰底/黑字大標題 | 服務架構說明、API／部署拓撲、內部依賴圖、系統設計文件，想要強烈的「圖像化系統視覺」而不是知識型白皮書感 |

## 選擇流程

1. 用 `ask_user` 詢問這份文件的情境基調，並提案 2-3 個最相關主題（不要一次列出全部 5 個選項造成選擇困難，除非使用者主動要求看全部）。
2. 讀取選定主題檔案的完整內容，複製其 `<style>` 與元件 HTML 結構到輸出文件。
3. 把 `assets/sidebar-layout-template.html` 的 `--doc-*` 變數換成該主題檔開頭註解列出的對應值。
4. 章節內容區塊（`.doc-section` 內部）沿用該主題原本的元件 class（例如 `wp-card`、`msq-card`、`medchart`、`tl-event` 等），不要混用不同主題的元件 class。

## 注意事項

- `organic-glass-style` 與 `cozy-meadow-style` 沒有像 `.wp`/`.msq` 那樣的頁面級 wrapper class，只需要在 `.doc-content` 內直接使用它們的卡片/區塊 class 即可，不影響 sidebar 骨架運作。
- `case-file-style` 整套字體是等寬字（Courier New / Consolas），若章節內文有大量中文說明，只有標籤、代號、程式碼片段用等寬字，一般描述段落仍可用系統預設襯線體，避免整頁閱讀吃力。
