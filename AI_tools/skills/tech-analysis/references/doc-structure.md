# 技術分析文件標準結構

Allen 所有的鏈路分析文件都應遵循此結構。

---

## 文件元素清單

### 必要元素

| 元素 | 目的 | 說明 |
|------|------|------|
| **標題與定位宣告** | 30 秒定位 | 說明這個 API/功能是什麼、在整個流程的第幾步 |
| **全貌鏈路圖** | Big Picture | 用 ASCII 圖呈現入口→本體→出口，標示涉及的專案 |
| **觸發條件** | When & Why | 什麼情境、哪個上游呼叫、在什麼情況下才會到這裡 |
| **逐步流程** | Step by Step | 按執行順序列出，每步說明「做什麼 + 為什麼」 |

### 選用元素（依分析深度加入）

| 元素 | 目的 | 何時加入 |
|------|------|----------|
| **分支決策表** | 消除歧義 | 有 if/else、ReturnCode、switch 時一律用表格 |
| **狀態流轉圖** | 狀態機 | 有訂單狀態、付款狀態等時必加 |
| **例外處理一覽** | 容錯地圖 | 有多種 Exception → 不同結果時整理成表 |
| **關鍵資料說明** | 資料生命週期 | 有貫穿多個階段的核心資料（如 k 值）時說明其生命週期 |
| **Request / Response 格式** | API 合約 | 分析 API 端點時加入，列出欄位與型別 |
| **關鍵檔案索引** | 快速導航 | 永遠加入，讓讀者知道改哪裡、看哪裡 |

---

## 標準編排順序

```
# {主題名稱} — 鏈路分析

> 分析日期、涉及專案

---

## 一、在整個流程中的位置（Big Picture）
    用 ASCII 圖標示此功能在完整使用者旅程中的位置

## 二、觸發條件
    - 哪個上游服務/專案呼叫
    - 在什麼用戶操作後觸發
    - 前置條件

## 三、Request / Response 格式（API 分析時加入）
    - Endpoint、Method
    - 主要欄位說明

## 四、核心流程（逐步）
    依執行順序說明，可用 ASCII tree 或編號清單

## 五、分支決策 / ReturnCode 對照
    必須用表格，禁止用純文字描述

## 六、狀態流轉圖
    有狀態轉換時必加，ASCII 或 Mermaid 皆可

## 七、例外處理一覽
    Exception → 結果/導頁/補救 的對應表

## 八、關鍵資料說明（選用）
    貫穿流程的核心資料，說明產生→傳遞→消費的完整路徑

## 九、特殊案例 / 備註
    HK/MY 差異、版本差異、已知 workaround 等

## 十、關鍵檔案索引
    | 角色 | 路徑 |
    每個主要的 Controller / Service / Processor 都要列
```

---

## 各元素的撰寫規範

### 全貌鏈路圖

```
用戶操作
    ↓
[專案A] ServiceA.MethodA()
    ↓ HTTP POST /api/xxx
[專案B] ControllerB.ActionB()
    ↓
[專案B] ServiceB.Process()
    ↓ HTTP POST /api/yyy
[專案C] ControllerC.ActionC()  ← 本文件的分析起點
    ↓
...
```

### 分支決策表格

```markdown
| 條件 / ReturnCode | 對應行為 | 最終結果 |
|------------------|----------|----------|
| Success          | 更新DB、觸發Processor | 導至完成頁 |
| Failed           | 取消付款請求 | 導至購物車 |
| Expired          | 取消訂單 | 導至訂單列表 |
```

### 狀態流轉圖

```
[初始狀態]
    │
    ├─ 條件 A → [狀態 X] → 後續動作
    ├─ 條件 B → [狀態 Y] → 後續動作
    └─ 條件 C → [狀態 Z] → 後續動作
```

### 關鍵檔案索引（表格格式）

```markdown
| 角色 | 路徑 |
|------|------|
| Controller | `專案/路徑/XxxController.cs` |
| Service | `專案/路徑/XxxService.cs` |
| Processor 定義 | `專案/路徑/ProcessorDefinitionCenter.cs` |
```

## 文件品質檢查清單

完成文件後，對照以下清單：

- [ ] 全貌鏈路圖清楚標示涉及哪些專案
- [ ] 觸發條件說明了「為什麼在這步做這件事」
- [ ] 所有 if/else 都已轉成表格
- [ ] 有狀態的流程已有狀態流轉圖
- [ ] 例外處理有集中整理（不散落在各段落）
- [ ] 關鍵檔案索引已加入
- [ ] 文件結尾向 Allen 回報「缺少哪些元素」
