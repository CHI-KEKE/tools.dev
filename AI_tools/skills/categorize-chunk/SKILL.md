# OUTPUT RULES

請嚴格遵守以下規則：

1. 最終輸出必須且只能為合法 JSON Array，輸出內容必須以 `[` 開頭並以 `]` 結尾，不得包含任何其他文字、說明、Markdown 或 code block
2. 禁止輸出說明文字、註解、問候語或結語
3. 每個物件只能包含：
   * `category`
   * `content`
4. `category` 與 `content` 必須為非空字串
5. 禁止輸出 null
6. 禁止新增其他欄位

---

# CHUNKING RULES

* 原始文本中的重要業務資訊不得遺漏
* 以完整業務流程或完整知識點作為切片單位
* 每個切片都必須可被獨立理解
* `content` 應優先保留有助於理解語意的標題或章節脈絡，建議格式為「標題\n內容」
* 不可從句子中間截斷
* 過短且缺乏語意脈絡的內容，可與相鄰且語意接近的段落合併
* 過長內容可依子流程、子主題、FAQ 或獨立問題拆分
* 單一切片內容通常應控制在約 200～600 字的語意範圍，但應優先保持語意完整性、主題單一性與檢索可辨識性
* 避免將低關聯主題合併為單一大型切片
* 為提升檢索品質與切片獨立性，可有限度整合高度相關且分散於不同段落的同質性支援資訊（例如客服聯絡方式、退款聯絡資訊、查詢方式）
* 僅允許整合高度相關之同質性資訊，不得跨低關聯主題重新組織內容
* 同一 FAQ、子主題或章節中的內容，應優先保留原始語意關聯與結構

---

# CATEGORY RULES

* `category` 必須使用穩定、一致且可重用的業務分類名稱
* `category` 可進行有限度語意正規化（semantic normalization），不需完全等同原始章節名稱，但不得偏離原始內容主題
* 避免碎片化、過度細分或無法重用的分類名稱
* `category` 必須能合理代表 `content` 的主要資訊範圍
* 若內容同時包含多個低關聯核心主題，應優先重新切片
* 避免品牌名稱、具體數字、問句或操作指令
* 建議使用簡潔且可重用的中文名詞片語

正確範例：

* 訂單管理
* 物流配送
* 退款流程
* 會員申辦

錯誤範例：

* 如何修改訂單
* OOO品牌會員申辦流程
* 30倍點數活動
* 請先申請退款

# NORMALIZATION RULES

允許進行不影響原始語意的格式正規化，以提升可讀性與檢索品質。

允許：

* 移除 HTML 標籤、inline style、attribute 與純排版用途之結構
* 保留具有語意價值的文字內容、超連結文字與必要資訊
* 圖片、banner、純裝飾性內容或無語意價值之 HTML 元素可移除
* 清理多餘空白與無意義換行
* 將 HTML Entity 轉換為正常文字
* 可整理條列排版，但不得改變原始資訊順序與核心語意
* 允許不影響語意的機械式文字正規化（例如重複空白、HTML 雜訊）
* 為提升切片獨立性與檢索品質，可有限度整合高度相關且分散於不同段落的同質性支援資訊（例如客服聯絡方式、退款聯絡資訊、查詢方式）

禁止：

* 語義摘要
* 刪減重要內容
* 捏造資訊
* 不得新增原文不存在之業務資訊、規則、流程、條件或說明
* 修改原始業務規則、條件、限制、流程或政策
* 修改數值、時間、金額或比例
* 將原文改寫為摘要、結論或說明語句
* 不得基於理解自行推論、優化、補充或重新詮釋內容
* 不得省略原文中的提醒、限制、條件、例外、注意事項或補充說明
* 不得因語意理解而任意重組低關聯主題或重建文件結構
* 不得將原屬於特定 FAQ、子主題或章節之內容移動至其他低關聯主題
* 除允許之有限度資訊整合外，不應重新改寫、重新命名、重新摘要或重新描述原文
