# Hexo 建置、部署與線上驗證

適用於文章新增、修改或視覺優化完成後的交付檢查。驗證應由 agent 實際執行，不能只提供指令讓使用者自行確認。

## 1. 確認專案與本次範圍

- 從文章實際路徑定位 Hexo 根目錄，讀取 `_config.yml`、`package.json` 與目前主題的相關設定。不要直接套用另一個站點或技能中記錄的舊渲染器資訊。
- 比對同目錄正常文章，保留既有 `{% tabs %}`、分頁名稱與 Frontmatter。不要為了通過預覽而移除 tabs。
- 確認正式版與需要更新的 `-pure.md` 已同步，檢查本次 diff 與既有未提交修改。
- 這個流程中的部署會發布整個站點。使用者明確要求 `hd`、發布或已在同一工作中授權部署時，直接延續執行；只要求草稿、本機預覽或修改 skill 本身，不視為另外授權發布網站。

## 2. 先檢查實際建置輸出

- 在真正的 Hexo 專案執行 `hexo generate`，確認退出碼與完整 log。暫存站點可用於探索，但不能取代實際專案驗證。
- 從產出的 `public/` 找到該篇文章與其真實 permalink；文章位於子目錄時，網址可能含分類前綴，不能只憑 `.md` 檔名猜網址。
- 檢查輸出包含預期的 tabs 面板、CSS、Mermaid 來源與完整正文。搜尋是否有非範例用途的原樣 `{% tabs %}`、`{% mermaid %}`、被跳脫的 HTML 或 Markdown 表格殘留。
- 必須在瀏覽器打開 Hexo 產出的頁面，不能把編輯器的一般 Markdown 預覽當成 Hexo 結果。若使用者截圖有原樣標籤，先取得預覽工具或網址並重現，不直接斷言是使用者開錯。
- 記錄錯誤與警告，區分本次文章造成的問題與已存在的站點問題；不要因程序退出碼為 0 就忽略 log 中的失敗。

## 3. 執行 hd 完成建置部署

先用 `Get-Command hd` 檢查函式定義，確認目前的步驟與目標解析方式。Allen 的既有 `hd` 依序執行：

1. `hexo clean`
2. `hexo g`，即 `hexo generate`
3. `hexo d`，即 `hexo deploy`

必須明確傳入本次專案路徑。例如中文站點：

```powershell
hd 'C:\Users\Allen Lin\Desktop\Hexo'
```

不要依賴預設工作目錄；目前函式在未指定目錄且所在位置沒有 `_config.yml` 時，會預設到 `Hexo-en`。執行 clean 前，確認解析出的 public 與資料庫路徑屬於目標 Hexo 專案。

- 若 `hd` 尚未載入，從已確認的 PowerShell profile 載入函式；若不存在，才在同一專案依序執行等價命令，並說明此替代。
- 保存 log，確認三個階段皆成功，包含 git push 與 `Deploy done`。PowerShell 函式可能只顯示錯誤後 return，不能只看最外層程序的退出碼。
- 記錄本次部署提交 SHA 與遠端目標。失敗就停止後續成功宣告，不使用 force push、修改遠端或擴大部署範圍來跳過問題。

## 4. 等待正式站點發布最新版本

- `hd` 成功推送不等於 GitHub Pages 已發布。查詢此次提交對應的 Pages workflow／deployment，確認 SHA 相符且 conclusion 為 success。
- 從實際部署設定取得正式 host，搭配產出的 permalink 組成文章網址；Git remote 的 `.git` 後綴不屬於網站 host。
- 等待期間每次間隔約 15 至 30 秒，持續提供進度。前幾次 404 或舊內容可能是發布延遲，不應立刻重複部署。
- 以正式網址 HTTP 200，加上能辨認本次修改的正文、樣式或結構，確認不是舊版本。若無法查 Pages API，必須用線上內容與本次產物比對確認，並揭露無法取得的發布狀態。
- 發布失敗時查看該次 job log。若約 10 分鐘仍無法確認最新版本，回報實際狀態、SHA 與未完成項目，不持續盲目重新部署。

## 5. Agent 自行開啟正式網站檢查

使用可用的瀏覽器工具、Playwright 或背景瀏覽器自動化，導航到正式 HTTPS 網址。等待主題與 Mermaid 完成渲染後，保存截圖並實際用圖片檢視工具讀取。HTTP 抓取、DOM 數量與截圖檔存在都不能單獨取代視覺檢查。

依文章實際內容執行下列檢查：

| 檢查面向 | 通過條件 |
| --- | --- |
| 版本與樣式 | 最新正文與 CSS 已生效，無非預期原樣模板標籤。 |
| Tabs | 逐一點擊所有分頁；每次只有對應面板顯示，圖表與正文無遺失。保留原有 tabs 數量與結構，除非使用者要求調整。 |
| Mermaid | 所有預期圖表均渲染成功，無語法錯誤、重複 SVG、缺失箭頭、重疊文字或被裁切的關鍵資訊。 |
| 時序圖 | 參與者、生命線、呼叫／回傳箭頭與 alt 分支可辨識。隱藏分頁切換後與重新繪圖後仍正常。 |
| 版面 | 標題、卡片、表格與程式碼可讀，長 Key 能換行或在區塊內捲動；不能只看節點數就認定圖可讀。 |
| 桌面與手機 | 至少以一般桌面及約 390px 手機寬度檢查所有分頁；整頁無橫向溢出。寬圖若需捲動，限定在圖表區塊且內容可完整查看。 |
| 深色模式 | 主題有此功能時，實際操作切換按鈕，再檢查各分頁的文字對比與圖表重繪；不要只修改 DOM 屬性模擬。 |
| 補充互動 | 操作 details、文章內導覽等實際存在的控制元件，確認可用。 |
| 瀏覽器錯誤 | 檢查 console／例外，釐清與本次文章有關的錯誤，不能忽略 Mermaid 的非同步錯誤。 |

截圖至少涵蓋各 tab 的主要內容及手機版；長分頁需向下捲動檢查，不能只拍到頂端便視為全文通過。檢查 Mermaid 時確認箭頭引用的 SVG marker 沒有因隱藏面板或重複 ID 而消失。

## 6. 修正後重跑與交付

- 若發現排版、圖表或分頁問題，只修正本次文章及必要依賴；不要擅自移除 tabs、重設主題或覆寫其他文章。
- 有實質修正後重新本機建置與驗證；已授權部署的工作再跑 `hd`，等待新的發布提交完成，重查受影響的線上畫面及分頁切換。
- 如果只是等待發布、權限或外部資源問題，不反覆改文章或推送相同內容。相同錯誤重複發生且沒有新證據時，說明阻礙與已完成的驗證。
- 交付時列出正式文章連結、建置／部署結果、已檢查的畫面範圍，以及仍存在的限制。保留部署 log、驗證結果與截圖作為證據。
- 只有本機驗證時，明確寫「本機通過，尚未部署」；只有推送成功而尚未查線上時，寫「已推送，線上驗證未完成」。不能把「請自行刷新查看」當成驗證完成。
