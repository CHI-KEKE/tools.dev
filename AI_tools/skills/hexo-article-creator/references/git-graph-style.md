# Git Graph 品牌風

來源：Allen 提供的 `C:\Dev\pics-cloudflare\style\git.png`。這是依該圖片歸納的文章視覺方向，不是 Git 官方品牌規範；不依賴來源檔案持續存在。可搭配 `assets/components/git-graph-style.html` 的可選元件。

## 圖片觀察

- 畫面尺寸為 1280 × 720。主背景是 Git 橘紅 `#F05133`，以 `#F25D3B`、`#F46640` 等鄰近暖色的大型圓弧和斜向色塊增加層次。
- 中央是白色 Git 圖形與粗體小寫字標，視覺重心明確；外圍以細白線、圓形節點和分支構成 commit graph 聯想。
- 整體使用扁平色塊，沒有玻璃效果、霓虹光暈或厚重陰影。裝飾線條保持纖細，主圖形與標題保持厚重。
- 圖片不足以判斷確切字型名稱。文章使用系統無襯線字體，程式碼與指令才切換為等寬字體。

## 轉成文章的設計規則

| 用途 | 色碼 | 套用方式 |
|:---|:---|:---|
| Git 主橘 | `#F05133` | Hero、主要節點、章節短線與關鍵連線 |
| 珊瑚層次 | `#F25D3B` | Hero 背景圓弧與大面積裝飾 |
| 淺橘層次 | `#F46640` | Hero 次要圓弧與分區背景 |
| 純白 | `#FFFFFF` | Hero 標題、節點、連線與正文卡片 |
| 暖白 | `#FFF8F4` | 長文背景，屬閱讀用途延伸色 |
| 炭黑 | `#2D2928` | 標題、正文與深色終端機背景 |
| 暖灰 | `#E8D8D1` | 細邊框和次要分隔線，屬閱讀用途延伸色 |

- 採用「Git Graph 品牌風」時，開場可使用大面積橘紅 Hero；正文回到暖白或白色，避免整篇長文都以高飽和橘紅作底。
- Hero 使用大型圓弧、斜向色塊與白色 commit graph。節點數與分支只作裝飾，不得暗示文章內容存在相同數量的 commit 或流程分支。
- 正式關係圖的節點、箭頭與條件必須對應文章證據。commit 節點可作為視覺語彙，但仍要標示清楚的節點文字與分支條件。
- Git 主橘表示主題品牌與閱讀重點，不代表警告、失敗或未追蹤狀態。狀態差異同時使用標籤、形狀、線型與文字，不能只靠顏色。
- 工作目錄、Index、HEAD 之間有順序或比較關係時，使用連線圖、分層圖或 Before／After 圖。不要用三張互不相連的卡片取代關係。
- `.gitignore`、追蹤判斷等條件邏輯使用真正的決策樹，每條分支直接標示「是／否」或具體條件。
- 指令與輸出使用深炭色終端機。正文與表格保持淺色背景，避免把整篇做成暗色終端機介面。
- 元件採中小圓角、細框與極輕陰影。不要加入毛玻璃、立體按鈕、漸層發光或柔和糖果色卡片。
- 深色模式改用深炭背景、淺暖白文字與較亮的 Git 橘。保留扁平色塊，不增加光暈。

## 元件選用

`assets/components/git-graph-style.html` 提供以下可選元件，不是固定版型：

- `gg-hero`：文章開場橫幅，使用圓弧與 commit graph 裝飾。
- `gg-three-zone`：呈現 Working Tree、Index、HEAD 等有明確比較關係的三個區域。
- `gg-decision`：呈現追蹤與 ignore 判斷的條件分支。
- `gg-steps`：呈現實驗中有先後順序的狀態快照。
- `gg-before-after`：呈現指令執行前後的差異。
- `gg-table-scroll`：呈現同條件比較表。
- `gg-note`：呈現補充、重要結論或範圍限制。
- `gg-code`、`gg-pre`：呈現簡短終端機範例；長篇文章也可以沿用站點 fenced code block，再由文章樣式統一外框與底色。

## 使用與驗證

先依 `SKILL.md` Step 1 確認文章風格與逐段呈現方案。本文件與範本提供素材，不要求每篇 Git 文章固定使用全部元件，也不授權修改或發布文章。

CSS 限定於 `gg-` 前綴元件；全頁程式碼樣式只能放在該篇文章的 `<style>` 中。HTML 全部頂格書寫，`pre` 內不留空白行。決策樹和三區圖在手機版改成單欄，由標籤文字保留關係，不以位置或顏色作唯一線索。

套用時依 `hexo-conventions.md` 與既有建置流程檢查桌面、約 390px 手機、深色模式、所有 tabs、表格水平捲動與程式碼右側留白。範本本身不代表已在文章中驗證。
