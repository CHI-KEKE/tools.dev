# Domain Sync Executor — 輸出格式範本

---

## 狀態標籤定義

| 標籤 | 意義 |
|------|------|
| `[草稿已產出]` | 異動明確，已產出 diff 格式草稿，信心程度 High/Medium |
| `[需人確認]` | 涉及業務語意，需開發者確認後才能更新 |
| `[新章節候選]` | domain.doc 無對應章節，建議新增 |
| `[跳過]` | 純重構，不影響 domain 描述 |

---

## 同步報告格式

```
domain-sync-executor report
────────────────────────────
觸發來源：<PR #xxx merged / Work Item #xxx Done>
Base：<base branch or commit>   HEAD：<HEAD commit>
────────────────────────────
§ <章節名稱>    [草稿已產出]  <一行摘要說明本次異動>
§ <章節名稱>    [需人確認]   <一行說明為何需確認>
§ <章節名稱>    [新章節候選]  <建議新增的章節標題>
§ <功能名稱>    [跳過]       純重構，無 domain 影響
────────────────────────────
直接草稿：N 項 | 待確認：N 項 | 新章節候選：N 項 | 跳過：N 項
════════════════════════════
```

---

## [草稿已產出] 輸出格式

```
§ <章節名稱>  [信心程度: High | Medium]
來源：commit <hash> / <檔案路徑>#L<行號>

- <舊內容行>
+ <新內容行>

說明：<一段話解釋這個變更的業務意義>
```

---

## [需人確認] 輸出格式

```
§ <章節名稱>  [需人確認]
RECOMMENDATION：<說明為何 AI 無法單獨決定這個變更>

現有文件內容：
  「<節錄現有 domain.doc 的相關段落>」

建議改動方向：
  <AI 提出的可能改法，供人工參考>
```

---

## [新章節候選] 輸出格式

```
§ <建議章節標題>  [新章節候選]
根據推斷：<diff 中哪些檔案 / 行號觸發此推斷>

建議新增章節草稿：
## <章節標題>
<章節內容草稿>
```
