# .NET Translation AutoGen Skill

Auto-generated multilingual C# source files are **not** committed to version control.
They must be regenerated from the Translation Service before each build.
This skill detects when those files are missing or stale, regenerates them via Cake,
then re-runs the build and reports the final outcome.

---

## Step 1 — Confirm this is a translation-related failure

A build failure is likely caused by missing translation files when you see **multiple**
`CS0117` errors of the form:

```
'ClassName' does not contain a definition for 'SomePascalCaseMember'
```

where:
- Many errors point to **the same class** (e.g. `LotteryActivityService`, `Backend.General`, …)
- The missing member names look like PascalCase translation keys (e.g. `LotteryActivityActivityNotExist`)
- The failing class lives under a `Common.Translations` namespace or an `AutoGenerated/` folder

If in doubt, check whether `AutoGenerated/` under the translations project is empty or contains
outdated files — that confirms the diagnosis.

If the errors look unrelated to translations (e.g. missing NuGet packages, type mismatches in
non-translation files), do **not** run this skill; address the actual root cause instead.

---

## Step 2 — Locate `translation.cake`

Look for `translation.cake` starting from the repository root:

```powershell
$cakeFile = Get-ChildItem -Path . -Recurse -Filter "translation.cake" |
    Select-Object -First 1
if (-not $cakeFile) {
    Write-Error "translation.cake not found. Cannot auto-generate translations."
}
```

The working directory for all subsequent commands must be the **directory containing
`translation.cake`** (typically `src/`). `cd` to that directory before continuing.

---

## Step 3 — Restore dotnet tools

The `dotnet-cake` CLI is declared in `.config/dotnet-tools.json` at the repository root.
Restore it from the **repo root** (one level above `src/`):

```powershell
# Run from repo root
dotnet tool restore
```

Expected output: `Tool 'cake.tool' (version 'x.x.x') was restored.`

If restore fails because `.config/dotnet-tools.json` is missing, report the error and stop.
Do **not** attempt to install Cake.Tool manually unless the user explicitly asks.

---

## Step 4 — Run the translation Cake script

From the **directory containing `translation.cake`** (e.g. `src/`):

```powershell
dotnet-cake translation.cake --target="Init Translation" --verbosity=diagnostic
```

The `Init Translation` target runs three tasks in order:

| Task | What it does |
|------|--------------|
| `Install Translation-AutoGen-Tool` | Installs `nine1.translations.client.tools.autogen` from the private NuGet feed |
| `Fetch Modules` | Calls the Translation API to refresh the list of modules in `translation_config.json` (retries 3×; skips update if API is unavailable) |
| `Auto Gen modules` | Downloads multilingual data from S3 and writes the `AutoGenerated/*.cs` source files |

**Environment notes:**
- `buildEnv` defaults to `Debug` — S3 QA endpoint is used, which is correct for local development.
- Pass `--buildEnv=Release` only in CI/CD pipelines that target production.
- If `Fetch Modules` fails all retries, it preserves the existing `Modules` list in
  `translation_config.json` and continues — this is intentional, not an error.

**Success indicator:** exit code 0. Spot-check by confirming that `AutoGenerated/*.cs`
files have been written (non-empty directory, timestamps just updated).

If the Cake script exits non-zero, surface the error output to the user and stop —
do not attempt to continue to the build step.

---

## Step 4b — Verify generated files are complete (ETag cache issue)

After `Init Translation` succeeds, open the affected `AutoGenerated/*.cs` file and verify that:
- Each `/// <summary>` comment block is **immediately followed** by a `public static string PropertyName =>` line
- The class contains **at least one property**

**If the class has XML comments but NO properties**, the i18n manifest ETag cache caused
the auto-gen tool to skip downloading the latest data from S3 (it saw "No Change" and
reused stale data). Fix:

1. Run `scripts/fix-etag-cache.ps1` to clear the stale ETag:

   ```powershell
   .\scripts\fix-etag-cache.ps1 -ModuleName "backend.general"
   ```

   - `-ModuleName`：指定受影響的 module 名稱（省略則清除全部）
   - 腳本預設 manifest 路徑為 `src\Common\Nine1.Livebuy.Common.Translations\i18n\Nine1.Livebuy\i18n.manifest`；若路徑不同，加上 `-ManifestPath` 參數

2. Re-run the Cake script:

   ```powershell
   dotnet-cake translation.cake --target="Init Translation"
   ```

3. Confirm the affected `.cs` file now contains `public static string` properties, then
   proceed to Step 5.

> **Why this happens:** The auto-gen tool uses ETags to avoid redundant S3 downloads.
> If a key is newly published to the Translation Service *after* the local ETag was cached,
> the tool sees the ETag still matches and skips the download — leaving the generated class
> with only XML comments and no properties.

---

## Step 5 — Re-run the build

After successful translation generation, run `dotnet build` on the solution:

```powershell
dotnet build <solution-file> --no-incremental 2>&1
```

Use `--no-incremental` so the newly generated files are picked up by the compiler.

**Success:** Exit code 0. Report:
- ✅ Build succeeded
- Warning count (StyleCop SA-series warnings are expected and can be noted without alarm)
- Output binary paths (lines containing ` -> `)

**Failure:** Exit code non-zero. Extract and display only `error CS` lines, then diagnose:

| Remaining error pattern | Likely cause |
|-------------------------|--------------|
| CS0117 on the **same** translation class, but `.cs` file has XML comments without properties | ETag cache in `i18n.manifest` — follow Step 4b to clear ETags and re-run |
| CS0117 on the **same** translation class | `Auto Gen modules` ran but couldn't fetch the module — check network / Translation Service availability |
| CS0246 `type … not found` | A new entity class is referenced but not yet created — this is a missing source file, not a translation issue |
| CS0117 on a **different** class (e.g. `BatchUploadTypeDefEnum`) | A NuGet package is missing a new enum value — translation generation is not the fix |
| Unrelated errors | Translation is no longer the root cause; investigate separately |

---

## Step 6 — Report summary

Always finish with a clear summary:

```
## Translation AutoGen Result

| Step | Status | Detail |
|------|--------|--------|
| Tool restore | ✅ / ❌ | … |
| Cake Init Translation | ✅ / ❌ | Duration: Xs |
| dotnet build | ✅ / ❌ | Errors: N, Warnings: N |

AutoGenerated files written: <count> .cs files
```

If the build still fails after generation, list the **remaining** errors grouped by error code
so the developer knows exactly what to fix next.
