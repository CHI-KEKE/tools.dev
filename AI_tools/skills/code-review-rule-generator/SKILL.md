*Skill Instructions*

## Overview

此 skill 專門用於產生程式碼審查規則文件，根據使用者提供的規則內容，自動產生中文和英文兩個版本的 Markdown 文件。每個規則文件都遵循統一的格式標準，包含規則編號、嚴重性、語言、問題說明、不合規範例、合規解決方案等完整資訊。

**使用時機**：
- 需要建立新的程式碼審查規則文件
- 需要將現有規則標準化為雙語版本
- 需要確保規則文件格式一致性

## 文件產生工作流程

當使用者提供規則內容時，請按照以下步驟執行：

### 0. **確認輸出目錄**
   - 在產生任何文件之前，**必須先詢問使用者**：「請問要將檔案儲存到哪個目錄？」
   - 預設建議路徑：`knowledge_base/backend/CustomRules`
   - 等待使用者確認或提供路徑後，才繼續後續步驟
   - 將產生的檔案儲存至使用者指定的目錄

### 1. **解析輸入內容**
   - 識別規則的關鍵資訊：規則編號(Key)、嚴重性(Severity)、語言(Language)等
   - 提取問題描述、不合規範例、合規解決方案
   - 識別額外的建議或最佳實踐

### 2. **產生英文版本**
   - 檔案命名：`N{編號}.md` (例如：N00022.md)
   - 使用標準英文規則格式(參考 `references/english_template.md`)
   - 確保程式碼範例的註解為英文
   - 檢查專業術語使用的正確性

### 3. **產生中文版本**
   - 檔案命名：`N{編號}_中文.md` (例如：N00022_中文.md)
   - 使用標準中文規則格式(參考 `references/chinese_template.md`)
   - 程式碼範例的註解翻譯為中文
   - 保持技術術語的準確性

### 4. **格式驗證**
   - 確認所有必要章節都已包含
   - 檢查 Markdown 語法正確性
   - 驗證程式碼區塊的語法高亮標記
   - 確保中英文版本內容對應一致

## 標準文件結構

每個規則文件都應包含以下章節：

### 必要欄位
- **標題**：簡潔描述規則目的
- **Metadata**：Key, Repository, Created At, Severity, Status, Language
- **Why is this an issue?**：說明為何這是個問題
- **Noncompliant Code Example**：不合規的程式碼範例與問題說明
- **Compliant Solution**：合規的解決方案與說明

### 選擇性欄位
- **Additional Recommendations**：額外建議(如：程式碼審查要點、靜態分析工具設定等)
- **Resources**：相關資源連結
- **Exceptions**：例外情況說明

## 格式規範

### Metadata 格式
```markdown
# [規則標題]

- **Key**: N00000  
- **Repository**: [repository name]  
- **Created At**: YYYYMMDD  
- **Severity**: [BLOCKER|CRITICAL|MAJOR|MINOR|INFO]  
- **Status**: [READY|BETA|DEPRECATED]  
- **Language**: [C#|Java|JavaScript|...]  

---
```

### 程式碼範例格式
- 使用適當的語法高亮標記 (例如：```csharp, ```java)
- 包含清晰的註解說明
- 突出顯示關鍵問題或改善點
- 保持範例簡潔但完整

### 章節分隔
- 使用 `---` 分隔主要章節
- 使用 `##` 表示主要標題
- 使用 `###` 表示次要標題

## Tips and Best Practices

### 內容撰寫
1. **明確性**：確保問題描述清晰明確，避免模糊不清
2. **完整性**：提供足夠的背景資訊和上下文
3. **實用性**：使用實際的程式碼範例，而非過於簡化的案例
4. **一致性**：在中英文版本之間保持內容一致性

### 程式碼範例
1. **代表性**：選擇能充分說明問題的典型案例
2. **對比性**：不合規和合規範例應形成明確對比
3. **可執行性**：盡可能提供可編譯/可執行的程式碼
4. **註解完整**：適當添加註解幫助理解

### 翻譯品質
1. **術語統一**：使用一致的技術術語翻譯
2. **自然流暢**：中文版本應該讀起來自然，不應有翻譯腔
3. **保留關鍵字**：程式碼中的關鍵字、類型名稱等保持英文
4. **文化適應**：根據目標語言調整表達方式

### 檢查清單
在產生文件後，請確認：
- [ ] 檔案命名正確 (N00XXX.md 和 N00XXX_中文.md)
- [ ] Metadata 完整且格式正確
- [ ] 所有必要章節都已包含
- [ ] 程式碼範例語法正確
- [ ] 中英文版本內容對應
- [ ] Markdown 格式正確
- [ ] 無拼寫或語法錯誤

## 常見情況處理

### 處理不完整的輸入
如果使用者提供的資訊不完整：
1. 根據上下文合理推斷
2. 對於關鍵資訊(如 Key、Severity)，詢問使用者
3. 在文件中標註需要補充的部分

### 處理複雜規則
對於複雜的規則：
1. 分解為多個子問題
2. 使用多個程式碼範例說明不同情況
3. 在 Additional Recommendations 中提供詳細指導

### 處理特定語言特性
針對不同程式語言：
1. 使用該語言的慣用術語
2. 遵循該語言的命名和格式慣例
3. 參考該語言的官方風格指南
