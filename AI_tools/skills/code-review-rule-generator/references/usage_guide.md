# 規則產生器 - 使用指南

此文件說明如何使用 code-review-rule-generator skill 來產生程式碼審查規則文件。

## 快速開始

### 基本使用方式

當您需要產生新的程式碼審查規則時，請提供以下資訊：

```
我需要產生一個新的程式碼審查規則：

[在此貼上您的規則內容，包含：
- 規則編號 (Key)
- 問題描述
- 不合規範例
- 合規解決方案
- 任何額外建議]
```

### 輸入格式

您可以用以下任一方式提供內容：

**方式 1：結構化輸入**
```
Key: N00055
Title: [規則標題]
Severity: MAJOR
Language: C#

問題描述：
[說明為何這是問題...]

不合規範例：
[程式碼範例...]

合規解決方案：
[程式碼範例...]
```

**方式 2：自然語言描述**
```
我想建立一個關於 [主題] 的規則，
這個問題是 [問題描述]，
不好的做法像是 [範例]，
應該要 [正確做法]...
```

## 產生前確認

在產生文件之前，Skill 會先詢問：

> 「請問要將檔案儲存到哪個目錄？」

- 預設建議路徑：`knowledge_base/backend/CustomRules`
- 使用者可提供任意絕對或相對路徑
- 確認路徑後才開始產生文件

## 輸出說明

Skill 會自動產生兩個檔案：

1. **N00XXX.md** - 英文版本
2. **N00XXX_中文.md** - 中文版本

兩個檔案將包含：
- 完整的 Metadata
- 格式化的章節結構
- 程式碼範例與說明
- 額外建議(如適用)

## 範例對話

### 範例 1：完整資訊

**使用者：**
```
請幫我產生規則文件：

Key: N00016
Title: Ensure Properties with "Utc" in Their Names Use DateTimeOffset
Severity: MAJOR
Language: C#

問題：Entity 屬性名稱包含 "Utc" 應該使用 DateTimeOffset 而非 DateTime

不合規範例：
public DateTime CreateDateTimeUtc { get; set; }

合規解決方案：
public DateTimeOffset CreateDateTimeUtc { get; set; }
```

**AI 回應：**
AI 會產生完整的 N00016.md 和 N00016_中文.md 檔案

### 範例 2：部分資訊

**使用者：**
```
我想建立一個規則，要求在查詢時必須包含 StoreId 以防止跨店存取
```

**AI 回應：**
AI 會詢問缺少的資訊：
- 規則編號
- 嚴重性
- 程式語言
- 具體的程式碼範例

然後產生完整文件

## 最佳實踐

### 提供資訊時
1. **盡可能完整**：提供所有已知資訊
2. **包含範例**：實際的程式碼範例比描述更有幫助
3. **說明原因**：解釋為何這是問題
4. **提供背景**：相關的技術背景或標準

### 檢查輸出時
1. **驗證內容準確性**：確認技術內容正確
2. **檢查程式碼**：確保程式碼範例可編譯
3. **確認翻譯**：中文版本是否自然流暢
4. **核對對應**：中英文版本內容是否一致

## 常見問題

### Q: 如果不知道規則編號怎麼辦？
A: 可以先使用臨時編號(如 N00000)，之後再更新

### Q: 程式碼範例需要多詳細？
A: 應該足以說明問題，但不要過於複雜。通常 5-15 行程式碼即可

### Q: 可以一次產生多個規則嗎？
A: 建議一次產生一個規則，以確保品質

### Q: 如何更新現有規則？
A: 提供規則編號和需要更新的內容，AI 會產生新版本
