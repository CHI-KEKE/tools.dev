# common-translation-workflow

91APP 系統多語系（i18n）抽離完整流程 Skill。

## 用途

當需要將程式碼中的硬編碼中文訊息抽離為系統多語系時使用。  
涵蓋從命名、註冊 Module、建立 Keys、產生 AutoGenerated 類別，到重構 Service 的完整流程。

## 主要操作介面：MCP 工具

**所有 Language Tool 操作優先使用 MCP 工具**（`translation_*`），不需要手動組 REST API。

### 查詢類（無需 Token，直接呼叫）

| MCP 工具 | 說明 |
|----------|------|
| `translation_list_projects` | 列出所有 Project |
| `translation_get_project` | 取得 Project 詳情（含語系清單） |
| `translation_list_modules` | 列出 Project 所有 Module |
| `translation_get_module` | 取得 Module 及其所有 Key |
| `translation_get_translation_key` | 取得特定 Key 的所有語系翻譯 |
| `translation_check_key_exists` | 確認 Key 是否存在 |
| `translation_get_module_by_fullkey` | 依 FullKey（module.key）取得翻譯 |

### 管理類（需先注入 Token）

| MCP 工具 | 說明 |
|----------|------|
| `translation_set_token` | 注入 Firebase JWT Token |
| `translation_ensure_module_exists` | 確保 Module 存在（不存在則建立） |
| `translation_add_translation_key` | 新增翻譯 Key（含多語文字） |
| `translation_update_translation_texts` | 更新翻譯文字 |
| `translation_add_translation_tag` | 新增標籤 |
| `translation_remove_translation_tag` | 移除標籤 |
| `translation_publish_module` | 發佈 Module |
| `translation_auto_translate` | AI 自動翻譯（結果需人工確認） |

## Firebase Token 取得（僅寫入操作需要）

> ⚠️ **查詢操作不需要 Token**，跳過此步驟直接呼叫查詢類 MCP 工具即可。

**Step 1：用 playwright-cli 從使用者的 Chrome 取得 Token**

```powershell
# 連接使用者已開啟的 Chrome（session name 用 chrome，非 existing）
playwright-cli -s=chrome tab-list   # 找到 Language Tool 的 tab index

# 切換至 Language Tool tab
playwright-cli -s=chrome tab-select <index>

# 從 IndexedDB 取得 Firebase Token
$result = playwright-cli -s=chrome run-code "async page => {
  const token = await page.evaluate(async () => {
    const db = await new Promise((res, rej) => { const r = indexedDB.open('firebaseLocalStorageDb'); r.onsuccess = e => res(e.target.result); r.onerror = rej; });
    const all = await new Promise((res, rej) => { const r = db.transaction('firebaseLocalStorage','readonly').objectStore('firebaseLocalStorage').getAll(); r.onsuccess = e => res(e.target.result); r.onerror = rej; });
    const entry = all.find(x => x && x.value && x.value.stsTokenManager);
    return entry ? entry.value.stsTokenManager.accessToken : 'NOT_FOUND';
  });
  return token;
}"
$token = ($result | Select-String -Pattern '^"ey').Line.Trim('"')
$token | Out-File "$env:TEMP\lt_token.txt" -Encoding utf8 -NoNewline
```

> ⚠️ **注意**：用 `-s=chrome`（附加到使用者真正的 Chrome），不是 `-s=existing`（會開新的 headless Chrome）。
> 若 Chrome 中沒有 Language Tool tab，先開啟 `https://translation.qa.91dev.tw` 並登入。

**Step 2：注入 Token 至 MCP**

```powershell
$token = Get-Content "$env:TEMP\lt_token.txt" -Raw
# 呼叫 translation_set_token MCP 工具，將 $token 傳入
```

**fallback：使用者自行提供 Token**

若 playwright-cli 無法取得，請使用者手動取得後直接貼給 Copilot：

1. 開啟 `https://translation.qa.91dev.tw` 並以 Google 帳號登入
2. 按 `F12` → **Network** → 篩選 **Fetch/XHR**
3. 重新整理頁面，找到 `getAccountInfo` 請求 → **Payload** → 複製 `idToken` 的值
4. 將 token 貼給我，我會呼叫 `translation_set_token` 注入

> Token 有效期約 **1 小時**，過期後重新取得。

## 流程總覽

```
前置 0：判斷專案類型（.NET / .NET Framework）
前置 1：推導 Module 命名（CamelCase → snake_case + 前綴）
Step 1：註冊 Module（translation_config.json 或 TranslationSettings.cs）
Step 2：Language Tool 建立 Keys 並 Publish
  2-1. 查詢 Module ID
  2-2. 新增翻譯 Key（並 Publish）
  2-3. 建立 EPIC / Page Tag【選用，未提供名稱需詢問】
  2-4. 將 Tag 綁定至每個翻譯 Key【選用，接續 2-3】
Step 3：產生 AutoGenerated 類別（translation.cake 或 generate.tt）
Step 4：重構 Service（加 using + 替換靜態屬性）
```

## 關鍵差異（.NET Framework vs .NET）

| 項目 | .NET Framework（NineYi.Sms） | .NET（Nine1.Live.Buy） |
|---|---|---|
| Module 設定 | `TranslationSettings.cs` 陣列 | `translation_config.json` |
| 產生工具 | T4 範本（`generate.tt`） | `translation.cake` CLI |
| 執行方式 | VS → 右鍵 `generate.tt` → Run Custom Tool（或 TextTransform.exe 腳本） | `dotnet-cake translation.cake --target="Init Translation"` |
| 執行前提 | 需先 Build 專案 | `dotnet tool restore` |
| 支援語系 | `zh-TW`、`en-US`（2 個） | 7 個語系 |
| 靜態屬性語法 | `{ get { return GetString(...); }}` | `=> GetString(...)` |
| 命名空間根 | `NineYi.Sms.Translations` | `Nine1.Livebuy.Common.Translations` |
| AutoGenerated 進 git | ✅ 需 commit | ❌ 不進 git |
