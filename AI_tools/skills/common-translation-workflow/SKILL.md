# 91APP 多語系（i18n）抽離完整流程

---

## ⚡ 主要操作介面：MCP 工具

**所有 Language Tool 操作優先使用 MCP 工具（`translation_*`），不需要手動組 REST API。**

### 查詢類 MCP 工具（無需 Token，直接呼叫）

| MCP 工具 | 說明 |
|----------|------|
| `translation_list_projects` | 列出所有 Project |
| `translation_get_project` | 取得 Project 詳情（含語系清單） |
| `translation_list_modules` | 列出 Project 所有 Module |
| `translation_get_module` | 取得 Module 及其所有 Key |
| `translation_get_translation_key` | 取得特定 Key 的所有語系翻譯 |
| `translation_check_key_exists` | 確認 Key 是否存在 |
| `translation_get_module_by_fullkey` | 依 FullKey（module.key）取得翻譯 |

### 管理類 MCP 工具（需先注入 Token）

| MCP 工具 | 說明 |
|----------|------|
| `translation_set_token` | 注入 Firebase JWT Token（僅存於記憶體） |
| `translation_ensure_module_exists` | 確保 Module 存在（不存在則建立） |
| `translation_add_translation_key` | 新增翻譯 Key（含多語文字） |
| `translation_update_translation_texts` | 更新翻譯文字 |
| `translation_add_translation_tag` | 新增標籤 |
| `translation_remove_translation_tag` | 移除標籤 |
| `translation_publish_module` | 發佈 Module |
| `translation_auto_translate` | AI 自動翻譯（結果需人工確認） |

### 🔄 MCP 不可用時的 Fallback（REST API）

當 `translation_*` MCP 工具無法使用時，改以 `Invoke-RestMethod` 直接呼叫 Translation Service REST API。

**Base URL（QA）：** `https://translation.qa.91dev.tw`
**認證：** `Authorization: Bearer {Firebase JWT Token}`（取得方式同下方 Token 流程）

| 操作 | 方法 | 路徑 |
|------|------|------|
| 確認 / 建立 Module | `POST` | `/api/v3/projects/{project}/modules` |
| 查詢 Module 及所有 Keys | `GET` | `/api/v3/projects/{project}/modules/{module}` |
| 新增翻譯 Key | `POST` | `/api/v3/modules/{moduleId}/translations` |
| 更新翻譯文字 | `PATCH` | `/api/v3/modules/{moduleId}/translations/{key}/texts` |
| 發佈 Module | `POST` | `/api/v3/modules/{moduleId}/publish` |

**Invoke-RestMethod 範例：**

```powershell
$token   = Get-Content "$env:TEMP\lt_token.txt" -Raw
$headers = @{ Authorization = "Bearer $token"; "Content-Type" = "application/json" }
$base    = "https://translation.qa.91dev.tw"
$project = "NineYi.Sms"  # 替換成目標 Project

# 1. 確認/建立 Module（若已存在回傳現有資料，不重複建立）
$body = @{ module = "backend.service.product_keyword" } | ConvertTo-Json
$mod  = Invoke-RestMethod -Method POST -Uri "$base/api/v3/projects/$project/modules" `
        -Headers $headers -Body $body
# $mod.id 供後續步驟使用

# 2. 新增翻譯 Key
$body = @{
    key   = "your_key"
    texts = @(
        @{ locale = "zh-TW"; text = "中文文字" }
        @{ locale = "en-US"; text = "English Text" }
    )
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Method POST -Uri "$base/api/v3/modules/$($mod.id)/translations" `
    -Headers $headers -Body $body

# 3. 發佈 Module
Invoke-RestMethod -Method POST -Uri "$base/api/v3/modules/$($mod.id)/publish" -Headers $headers
```

### 🔑 Firebase Token 取得（僅寫入操作時執行）

> ⚠️ **查詢操作跳過此步驟**，直接呼叫查詢類 MCP 工具。

**用 playwright-cli 從使用者的 Chrome 取得 Token：**

```powershell
# 列出 Chrome 分頁，找到 Language Tool 的 tab index
playwright-cli -s=chrome tab-list

# 切換至 Language Tool tab（替換 <index>）
playwright-cli -s=chrome tab-select <index>

# 從 IndexedDB 取得 Firebase Token
$result = playwright-cli -s=chrome run-code "async page => {
  const token = await page.evaluate(async () => {
    try {
      const db = await new Promise((resolve, reject) => {
        const req = indexedDB.open('firebaseLocalStorageDb');
        req.onsuccess = e => resolve(e.target.result);
        req.onerror = reject;
      });
      const all = await new Promise((resolve, reject) => {
        const store = db.transaction('firebaseLocalStorage', 'readonly').objectStore('firebaseLocalStorage');
        const req = store.getAll();
        req.onsuccess = e => resolve(e.target.result);
        req.onerror = reject;
      });
      const entry = all.find(x => x && x.value && x.value.stsTokenManager);
      return entry ? entry.value.stsTokenManager.accessToken : 'NOT_FOUND';
    } catch(e) { return 'ERROR:' + e.message; }
  });
  return token;
}"
$token = ($result | Select-String -Pattern '^"ey').Line.Trim('"')
$token | Out-File "$env:TEMP\lt_token.txt" -Encoding utf8 -NoNewline
Write-Host "Token length: $($token.Length)"
```

> ⚠️ **注意**：使用 `-s=chrome`（附加到使用者真正的 Chrome），**不是** `-s=existing`（那會開新的 headless Chrome，沒有登入狀態）。
> 若 Chrome 中沒有 Language Tool tab，先讓使用者開啟 `https://translation.qa.91dev.tw` 並登入。

**取得後注入至 MCP：**

```powershell
$token = Get-Content "$env:TEMP\lt_token.txt" -Raw
# 呼叫 translation_set_token MCP 工具，傳入 $token
```

**fallback：使用者自行提供 Token**

若 playwright-cli 無法取得（如 Chrome 未開啟、無法附加等），請使用者依下列步驟手動取得：

1. 開啟 `https://translation.qa.91dev.tw` 並以 Google 帳號登入
2. 按 `F12` 開啟 DevTools → **Network** → 篩選 **Fetch/XHR**
3. 重新整理頁面，找到 `getAccountInfo` 請求 → **Payload** → 複製 `idToken` 的值
4. 將 token 直接貼給我，我會呼叫 `translation_set_token` 注入

> Token 有效期約 **1 小時**，過期後需重新取得。

## 情境 A：直接操作 Language Tool（透過 URL）

當使用者提供 Language Tool 的網頁 URL，或要求直接新增／修改某 module 的翻譯內容時，使用本情境。

### URL 格式識別

```
https://translation.qa.91dev.tw/web/{project_name}/{module_name}
```

| URL 片段 | 說明 | 範例 |
|----------|------|------|
| `{project_name}` | Language Tool 的 Project 名稱 | `Test20200423`、`NineYi.NMQV2` |
| `{module_name}` | Language Tool 的 Module 名稱 | `K250429`、`backend.service.product_keyword` |

> 💡 使用者若同時提供 `full key`（如 `K250429.K250505`），格式為 `{module_name}.{key_name}`。

### 情境 A - 修改翻譯、Publish（MCP 優先）

> 🔑 需先注入 Token（參考上方「Firebase Token 取得」流程），再呼叫 MCP 工具。

```
1. translation_set_token        → 注入 Token（寫入前）
2. translation_get_module_by_fullkey → 查詢 module 資訊（可確認 key 是否存在）
3. translation_update_translation_texts → 更新指定語系的翻譯文字
4. translation_publish_module   → 發佈上線
```

**支援的語系清單**

```
zh-TW、zh-HK、zh-CN、en-US、ja-JP、ms-MY、id-ID、ko-KR、th-TH、vi-VN
```

> 💡 .NET Framework 專案只需要 `zh-TW`、`en-US` 兩個語系。
> 💡 修改特定語系時，只需傳入要更新的語系，其他語系不受影響。


> 💡 **修改特定語系時，`$texts` 只需包含要更新的語系，其他語系不受影響。**

## 前置 -1：識別需抽離的文字

在開始流程前，**先掃描目標檔案，判斷哪些字串需要抽離為多語系 Key**。

### ❌ 不需要抽離

| 類型 | 範例 |
|------|------|
| Log 訊息（任何層級） | `_logger.LogError("fetch failed")` |
| 例外 / 錯誤訊息（Exception message） | `throw new Exception("invalid state")` |
| 純錯誤代碼（Error Code 常數） | `"ERR_NOT_FOUND"`、`"SALE_PAGE_001"` |
| 內部常數、設定值 | `"application/json"`、`"Bearer"` |

### ✅ 需要抽離（向前端傳送的資訊）

| 類型 | 範例 |
|------|------|
| API 回應的使用者可見訊息 | `return BadRequest("此商品已下架")` |
| 回傳給前端的 message / description 欄位 | `new ResultDto { Message = "操作成功" }` |
| 驗證失敗回應給使用者的提示文字 | `ModelState.AddModelError("", "數量不可為負數")` |

### ❓ 不確定時：主動詢問使用者

遇到以下情境時，**不要自行判斷，請先詢問使用者是否需要抽離**：

- 字串同時出現在 Log 與回應訊息（雙重用途）
- 字串是否為顯示給使用者看的訊息無法確認
- 任何模糊的情境

> 💬 **詢問範例：**
> 「`"查無此商品"` 這段文字是否會顯示給使用者？若是，我可以幫您抽離為多語系 Key。」

## 前置 1：確認 Module 命名

### 命名轉換步驟

1. 取得檔案名稱
2. 判斷類型（Controller / Service / Manager / Repository）
3. 去除類型後綴
4. **確認類別所在的 namespace 子層級**（資料夾路徑），將子層級轉為 snake_case 並插入前綴與類別名稱之間
5. CamelCase → snake_case（類別名稱本身）
6. 加對應層級前綴

### 檔案類型對應 Module 路徑

| 檔案類型 | Module 格式 | 範例 |
|---|---|---|
| `*Controller.cs`（webapi） | `backend.webapi.{name}` | `backend.webapi.sale_page` |
| `*Service.cs` | `backend.service.{name}` | `backend.service.product_keyword` |
| `*Manager.cs` | `backend.manager.{name}` | `backend.manager.sale_page` |
| `*Repository.cs` | `backend.repository.{name}` | `backend.repository.sale_page` |
| `*EntityValidator.cs` | `backend.validator.{name}` | `backend.validator.product_keyword_sku` |
| common | `backend.common.{module}` | `backend.common.salepage_category` |

> ⚠️ `*EntityValidator.cs` 去除後綴為 **`EntityValidator`**（不是 `Validator`）。
> 例：`ProductKeywordSkuEntityValidator` → 去除 `EntityValidator` → `ProductKeywordSku` → `product_keyword_sku`

### 命名規則

- **節點命名**：全小寫，單字間用底線 `_` 分隔（snake_case）
- **Key 命名**：全小寫，單字間用底線 `_` 分隔（snake_case）
- **根層**：`android` / `f2e` / `ios` / `backend`

> ⚠️ snake_case 是 Module 命名的**基本規則**。例外情況請見「特殊案例」。

### 子 namespace 的納入規則

當類別位於子資料夾（namespace）中時，**須將 namespace 最後一階轉為 snake_case 加入 Module 路徑**。

```
{前綴}.{namespace_最後一階}.{class_name}
```

**判斷依據：取類別所在 namespace 的最後一階（即類別檔案的直屬資料夾）**

例：
```
SCM\Frontend\BLV2\BatchUpload\BatchModifyLoyaltyPointService.cs
  namespace 最後一階 → BatchUpload → batch_upload
  前綴               → scm.service（SCM Frontend → scm.service）
  類別名稱           → BatchModifyLoyaltyPoint → batch_modify_loyalty_point

  → scm.service.batch_upload.batch_modify_loyalty_point
```

> ✅ `TranslationSettings.cs` 既有先例：
> ```
> scm.service.batch_upload.live_buy_batch_edit_keyword
> scm.service.batch_upload.sale_page_create
> scm.service.email.home_delivery_shipping_finish
> ```

### CamelCase → snake_case

```
SalePage        → sale_page
SalePageV2      → sale_page_v2
ProductKeyword  → product_keyword
BatchUpload     → batch_upload
```

### C# 命名空間格式

Language Tool Module 轉為 C# 命名空間：各片段首字母大寫，底線去除。

```
scm.service.batch_upload.batch_modify_loyalty_point
→ {TranslationRootNamespace}.Scm.Service.BatchUpload.BatchModifyLoyaltyPoint
```

> `TranslationRootNamespace` 依專案不同：
> - NineYi.Sms (.NET Framework) → `NineYi.Sms.Translations`
> - Nine1.Live.Buy (.NET) → `Nine1.Livebuy.Common.Translations`

### 範例

```
SCM\Frontend\BLV2\BatchUpload\BatchModifyLoyaltyPointService.cs
  → 去除 Service       → BatchModifyLoyaltyPoint
  → 子 namespace       → BatchUpload → batch_upload
  → snake_case         → batch_modify_loyalty_point
  → 加前綴             → scm.service.batch_upload.batch_modify_loyalty_point
  → C# 命名空間        → {Root}.Scm.Service.BatchUpload.BatchModifyLoyaltyPoint
```

## Step 1：註冊 Module

### .NET（translation_config.json）

位於 `Common/{ProjectName}.Common.Translations/translation_config.json`：

```json
{
  "Modules": [
    "...",
    "backend.service.product_keyword"
  ]
}
```

### .NET Framework（TranslationSettings.cs）

位於 `CrossLayer/Translations/TranslationSettings.cs`，在 `Modules` 陣列新增：

```csharp
public ModuleSetting[] Modules { get; private set; } = new ModuleSetting[]
{
    // ... 現有 modules
    new ModuleSetting { Name = "backend.service.product_keyword" },
};
```

> `NeedCodeGen` 預設為 `true`，不需特別指定。

## Step 2：在 Language Tool 建立 Keys 並 Publish

### 預覽 Module 網址

```
https://translation.qa.91dev.tw/web/{project_name}/{module_name}
```

例：`https://translation.qa.91dev.tw/web/NineYi.NMQV2/scm.service.batch_upload.live_buy_batch_edit_keyword`

### 2-1. 確保 Module 存在

使用 `translation_ensure_module_exists` MCP 工具（需 Token）：

```
translation_ensure_module_exists(projectName, moduleName)
→ 回傳 moduleId
```

### 2-2. 新增翻譯 Key

使用 `translation_add_translation_key` MCP 工具（需 Token）。

**業務規則：**

| 條件 | 說明 |
|------|------|
| Key 命名 | 全小寫 + 底線分隔（`^[\w]+$`，不可含 `.`） |
| 同 Module 下 Key 重複 | `409 Conflict`，用 `translation_check_key_exists` 先確認 |
| .NET Framework 語系 | 只需 `zh-TW`、`en-US` 兩個語系 |
| .NET 語系 | `zh-TW`、`zh-HK`、`zh-CN`、`en-US`、`ja-JP`、`ms-MY`、`th-TH` 等 7 個 |
| 新增後自動 Publish | ✅ 新增 Key 後即自動 Publish，通常不需另外呼叫 Publish |

### 2-3. 建立 Tag（EPIC / Page）【選用】

> ℹ️ **此步驟為選用。**
> - 若使用者**未提供** EPIC 名稱或 Page 名稱，**請主動詢問**。
> - 若使用者不需要標記 Tag，可跳過 2-3 與 2-4。

#### Tag 名稱格式規則

| 格式 | 說明 |
|------|------|
| EPIC Tag | `EPIC_` 前綴 + 自訂名稱，例如 `EPIC_聯合公園` |
| Page Tag | `PAGE_` 前綴 + 自訂名稱，例如 `PAGE_新世代` |
| **前綴不可省略** | `EPIC_` / `PAGE_` 是必要前綴，缺少會導致 Tag 分類錯誤 |

使用 `translation_add_translation_tag` MCP 工具（需 Token）：

```
translation_add_translation_tag(moduleId, key, tags: ["EPIC_聯合公園", "PAGE_新世代"])
```

- 每個 Key 需個別執行一次，不支援批次綁定

### 2-4. Publish

通常新增 Key 時已自動 Publish。若需手動 Publish 使用 `translation_publish_module` MCP 工具。

> 參考 `common-dotnet-translation-autogen` skill 執行完整步驟。

```powershell
# repo root

// Nine1.Livebuy.Common.Translations.Backend.Service
public class ProductKeyword

**方法 C：無 VS 環境（TextTransform.exe）**

安裝免費的 [Visual Studio Build Tools](https://aka.ms/vs/17/release/vs_BuildTools.exe) 即可取得 TextTransform.exe，無需完整 IDE。

> ⚠️ `dotnet-t4` 不適用此專案：專案 DLL 為 .NET Framework 編譯，在 dotnet-t4 的 .NET Core 執行環境下無法正確載入 `System.Runtime.Caching` 等 Framework 依賴。必須使用跑在 .NET Framework 上的 TextTransform.exe。

使用 `scripts/run-t4-generate.ps1`（自動偵測 TextTransform.exe 路徑）：

```powershell
.\scripts\run-t4-generate.ps1 -ProjectDir "<Translation 專案目錄>"
```

- **先 Build 專案**，確認 `bin\Debug\` 下的 DLL 已是最新版本
- 腳本會自動尋找 VS Professional / Enterprise / BuildTools 的 TextTransform.exe
- 執行後檢查 `AutoGenerated/` 目錄下的 `.cs` 檔案時間戳是否已更新

**成功產生的類別樣式：**

```csharp
// NineYi.Sms.Translations.Backend.Service
public class ProductKeyword
{
    public static string GetString(string key, string defaultValue = null) { ... }

    public static string YourKey { get { return GetString("your_key"); } }
}
```

> ✅ NineYi.Sms 的 AutoGenerated **進 git**，需將產生的檔案一併 commit。

> ⚠️ **新增檔案須加入 .csproj**：T4 若產生出新的 `.cs` 檔案，必須手動在 `.csproj` 加入對應的 `<Compile Include="...">` 節點，否則 Build 時不會編譯到。

> ⚠️ **確認異動範圍**：T4 執行後務必執行 `git diff --name-only` 確認是否有非預期的 AutoGenerated 檔案被修改，若有則用 `git checkout HEAD -- {file}` 還原，並確認 Build 無錯誤後才視為完成。

### 帶參數的翻譯文案（格式化字串）

當 Translation key 的文案含有 `{0}`、`{1}` 佔位符時（如 `"商品頁序號：{0}"`），**不應使用 `string.Format()`**，應使用 **安全格式化方法** 取代。

#### 為何需要安全格式化

Translation 文案在執行期從遠端（S3）讀取。若：
- 網路異常導致文案為 `null`
- 語系設定錯誤造成格式字串殘缺

`string.Format()` 會拋出 `ArgumentNullException` / `FormatException`，中斷整個業務流程。
安全格式化方法在格式化失敗時直接回傳原字串，不拋出例外。

#### 使用方式

```csharp
// Before（不安全）
string.Format(ProductKeyword.SalePageIdField, salePageId)

// After（安全）
StringUtility.PeacefulFormat(ProductKeyword.SalePageIdField, salePageId)
```

#### NineYi.Scm.NMQV2 專案

已有 `StringUtility.PeacefulFormat()`（`NineYi.Utility` 命名空間），直接使用：

```csharp
using NineYi.Utility;

// 單一參數
StringUtility.PeacefulFormat(ProductKeyword.SalePageIdField, salePageId)

// 多個參數
StringUtility.PeacefulFormat(ProductKeyword.SkuDuplicate, liveSessionId, skuId)
```

#### 其他專案（無現成方法時）

若專案中沒有對應的安全格式化方法，請自行建立靜態工具方法：

```csharp
/// <summary>
/// 不拋出例外的 string.Format 包裝。
/// 格式化失敗時（str 為 null 或佔位符數量不符），直接回傳原字串。
/// </summary>
public static string PeacefulFormat(string str, params object[] args)
{
    try
    {
        return string.Format(str, args);
    }
    catch
    {
        return str;
    }
}
```

> 建議放在專案既有的 StringHelper / StringExtensions 等工具類別中，避免重複定義。

## 特殊案例

### Definition（資料庫定義翻譯）

- Module：`backend.definition.{Definition_TableName}`
- Key：`{Definition_ColumnName}_{Definition_Code}`（**大小寫不變**）

> ⚠️ **`backend.definition.` 不套用 snake_case 規則**
>
> 因為 Module 名稱的最後一段（`{Definition_TableName}`）會直接對應資料庫的 Table 名稱，
> 而 DB Table 名稱本身是 PascalCase（例如 `BatchModifyLoyaltyPoint`），不需轉換。
>
> 正確：`backend.definition.BatchModifyLoyaltyPoint`
> 錯誤：`backend.definition.batch_modify_loyalty_point`

### Database（資料庫相關）

- Module: `backend.database.{entity_name}`

### Common（前台後台共用）

- Module: `backend.common.{module_name}`

### 多個 Repo 共用同一 Language Tool Project

有些專案的多個 repo 共用同一個 Language Tool Project，新增 key 時使用同一個 project name：

| Repo | Language Tool Project |
|------|----------------------|
| `NineYi.ERP.NMQV2` | `NineYi.NMQV2` |
| `NineYi.Scm.NMQV2` | `NineYi.NMQV2` |

> ⚠️ 在這類 project 中新增 key 時，須確認 key 名稱在**兩個 repo 的 AutoGenerated 檔案**中皆已同步，避免 cake 重跑後其中一個 repo 的 AutoGenerated 遺失新 key。
